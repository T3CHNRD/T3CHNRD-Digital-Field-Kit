# Quick Start

## Technician startup checklist

Use this when beginning a field or support session.

### 1. Establish scope

- identify the device and owner
- confirm the issue summary
- note whether the session is remote, on-site, or portable-drive based

### 2. Confirm environment

- workstation name and user context
- device role and OS version
- whether the session is admin-capable
- whether the tool should run in portable or installed mode

### 3. Gather baseline evidence

- recent error screenshots or logs
- device health summary
- recent service or app changes
- business context or user impact

### 4. Choose the right path

- diagnostics first for unknown or broad issues
- security review for account, endpoint, or suspicious behavior
- network checks for connectivity or routing issues
- repair flows for local configuration or maintenance actions
- deployment tasks for setup, imaging, or workstation restore

### 5. Run the appropriate tool

Start from the least invasive check, then move to more impactful actions only when necessary.

### 6. Record results

Write down:

- tool used
- result or status
- exit code or summary message
- follow-up action
- escalation point if needed

## Minimal decision tree

- If the issue is vague or intermittent: start with diagnostics
- If the issue is security-related: start with security review and baseline checks
- If the issue is connectivity-related: start with network flow
- If the issue is system health or repair: move to maintenance and repair actions
- If the issue is deployment: use setup/install-related workflows

## Exit criteria

Stop and document when:

- root cause is identified
- a repair is applied and validated
- a tool requires escalation or vendor involvement
- the device is restored to a known-good state
