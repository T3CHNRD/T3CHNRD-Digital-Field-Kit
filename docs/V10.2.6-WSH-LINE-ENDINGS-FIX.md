# v10.2.6 Windows Script Host line-ending fix

## Observed field failure

The v10.2.5 portable launcher failed immediately in Windows Script Host with:

- `OPEN-ME-GUI.vbs`
- line 214
- `Syntax error`
- code `800A03EA`

## Root cause

Inspection of the exact packaged v10.2.5 bytes showed that several generated infrastructure files used `CRCRLF` (`0D 0D 0A`) instead of canonical Windows `CRLF` (`0D 0A`).

`OPEN-ME-GUI.vbs`, `RUN-PORTABLE.vbs`, `RunnerBroker.vbs`, and `Runner-Diagnostics.vbs` contain VBScript underscore line continuations. The doubled carriage return inserts an extra physical blank line after the continuation marker, so Windows Script Host cannot compile the script and reports a later-line syntax error.

Affected generated infrastructure also included the installer PowerShell source and HTA shell, so the packaging correction is applied consistently to first-party infrastructure text.

## v10.2.6 correction

- Canonicalize first-party infrastructure text files to exact CRLF.
- Keep `.vbs` and `.cmd` files ASCII with no UTF-8 BOM.
- Explicitly reject `CRCRLF` during package validation.
- Explicitly verify that every VBScript continuation line is followed immediately by its continuation statement.
- Verify duplicate `Dim` declarations by scope.
- Leave the diagnostic `Scripts\` tree byte-for-byte unchanged.
- Re-extract the final ZIP and hash-compare every packaged file against the validated source tree.

## Validation

The v10.2.6 package passed 251 static/package checks with zero failures. The final ZIP contained 613 files; re-extraction produced 613 identical files with zero missing, extra, or changed files, and ZIP CRC validation passed.

Runtime execution still requires a Windows field test because the build environment cannot execute Windows Script Host, `mshta.exe`, UAC, Windows PowerShell 5.1, or the WinForms installer.
