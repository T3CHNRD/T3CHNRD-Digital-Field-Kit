# v10.2.3 Runner Error-Capture Fix

## Field evidence

The v10.2.2 Windows test reached `RunnerBroker.vbs` and failed with VBScript runtime error `800A0005` at the `TextStream.Write` call while the broker was attempting to report a PowerShell script-invocation failure.

## Verified source-level cause

The broker's PowerShell detail file was written as UTF-8. `ReadTextAnsiOrUnicode` attempted to open it first as UTF-16 Unicode. That could decode UTF-8 byte pairs into CJK-looking Unicode characters. The broker then tried to write that Unicode string through `FileSystemObject.CreateTextFile(..., unicode=False)`, producing the `Invalid procedure call or argument` exception at `TextStream.Write`.

This was an application error-reporting defect. It did not establish the root cause of the underlying local PowerShell script-invocation failure.

## v10.2.3 changes

- PowerShell broker detail is written with `-Encoding Unicode` (UTF-16LE).
- `broker.error` and broker launch-error files use a Unicode TextStream.
- Control markers such as ready/done remain simple ANSI text.
- `OPEN-ME-GUI.vbs` reads `broker.error` and the runner diagnostic report as Unicode.
- `Runner-Diagnostics.vbs` writes the diagnostic report and captured PowerShell detail as Unicode.
- Diagnostic scripts under `Scripts/` were not modified.

## Required Windows validation

If the broker still cannot invoke the local PowerShell self-test, the v10.2.3 report should preserve the actual PowerShell exception plus execution-policy, `Zone.Identifier`, signature, and direct script-invocation evidence. That evidence must be used before changing the working diagnostic scripts or attributing the problem to Defender/EDR/GPO.
